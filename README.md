# Map-O-Matic

**A free cartography studio that runs in your browser: style your data as a map, compose a print-ready layout, collect field data on phones, and gather your maps into an interactive atlas.**

Live tool: **[jonathancinnamon.com/map-o-matic](https://www.jonathancinnamon.com/map-o-matic/)**

Map-O-Matic pairs a GIS-style map builder with a print-layout composer, field data collector, and interactive atlas builder. Projects and datasets are organized on a home screen and stored in your browser.

![Map-O-Matic screenshot](img/screenshot.jpg)

## Modules

| Module | What it does |
|---|---|
| **Home** | A landing page listing all your projects (thumbnail, layer count, last edited) with rename/duplicate/delete/import/export, plus a Data Library shared across every project. |
| **Map Maker** | Add data by upload, from your library, or from online sources. The place search sits above **+ Add data** in the left panel (the 🔍 button under the on-map controls jumps to it). Choose from open vector and raster basemaps (or a blank canvas), or switch to any of 13 map projections with full pan/zoom/rotate. Symbolize with single symbol, unique values, graduated colour, or graduated point size. Filter, calculate new fields, browse the attribute table and field list, and run 18 spatial tools. |
| **Map Composer** | A drag-and-resize page composer: map frames, titles, legends, north arrows, calibrated scale bars, neatlines, images, inset maps, and functional templates. Group, align, distribute and lock elements. Exports to print-ready PDF or PNG. |
| **Field Mapper** | Design forms for mapping points, lines and areas with phones (text, numbers, dates, choices, notes, photos, audio), open them on any phone browser with a link or QR code, bring the data back by direct link, QR codes or file, and send them to Map Maker as layers. |
| **Atlas** | Build a book of maps: a cover, a contents page, and pages holding live interactive maps from Map Maker, finished layouts from Map Composer, images and formatted text. Reads as a flip-book with turning pages or as one scrolling page, and exports as a single web page to share. |

Maps sent to Map Composer are redrawn at four times the screen's pixel density before capture (basemap, symbols and labels), so frames print well above 300 dpi; atlas snapshots of live maps and layouts are taken at three times. The modules connect through **Send / Export ▾** at the right of the top bar, which lists what the current module can send and export. **Send / Export ▾ → Map Composer** (in Map Maker) — style your map in Map Maker, click once, and it lands on the layout page as a map frame with an auto-built legend (and a calibrated scale bar, when the map has one). The dialog first asks for the map title and each legend title, pre-filled with readable versions of the layer and field names, so the page never shows raw file names like *local-area-boundary_stats — pt_count*. Feature labels can come across as editable text objects rather than being baked into the image, so they can be nudged, restyled or removed on the page. Map Composer also works completely on its own: upload any styled map image and build a layout around it.

## Quick start

1. Open the tool. The first time, it creates a starter project; after that you land on the **Home** screen — open a project or start a new one.
2. **Map Maker:** click **+ Add data ▾** to upload a file, pull from your library, or fetch from an online source (Natural Earth, OpenStreetMap, an open-data portal, or any GeoJSON/CSV/feature-service URL). Use the search bar to jump to a place: type a name and press Enter (it drops a marker you can remove from its popup). Select a layer — each has its own **Table** and **Fields** buttons — to set its symbology, filter, and labels.
3. Click **Send to Composer**. Your styled map and a matching legend appear on the layout page automatically.
4. **Map Composer:** add a title, north arrow, and neatline from the toolbar, or start from a **Template** and double-click its placeholders to fill them. Drag, resize, and rotate anything; hide the side panel for more room.
5. **Send / Export ▾ → Export files…** for a print-ready PDF or PNG — or a georeferenced image, a zip of your data layers, or a full project archive.

The in-tool **Help** button covers everything in more depth.

## Projects, the data library, and where things live

Every project — its data, symbology, and layout — is stored in your browser (IndexedDB), listed on the **Home** screen with a thumbnail and last-edited time. The project dropdown in the top bar switches between them without a trip home; work autosaves as you go. Every dataset you add, from any source, lands in a shared **Data Library** reusable across all your projects — add it to a new project with **+ Add data → From my library**, where you can tick several datasets and add them all at once instead of re-fetching them one at a time. The Data Library tab on the Home screen also has a **Remove all** button that clears every dataset not currently used by a project (in-use datasets are kept and reported). The landing screen itself carries a short intro banner and a footer crediting the open libraries the tool is built on; clicking the **Map-O-Matic** wordmark from anywhere returns you there.

Because storage lives in the browser, it's tied to that browser on that computer. On a shared machine, download a project file or a full project archive (Export) before you leave — importing it elsewhere restores everything, including the datasets it uses.

Map-O-Matic asks the browser to keep its storage permanently (Safari otherwise clears a site's data after 7 days without a visit). When folder sync is off, the Home screen shows a **Back up your work** reminder for any project with three or more days of edits since its last export, with an Export button for each one. If browser storage is full, saving says so plainly instead of failing silently.

### Working across computers (optional)

The **☁ Sync to cloud** button in the top bar points Map-O-Matic at a folder you already sync — your OneDrive, Google Drive or Dropbox folder. Projects are then written there as ordinary files whenever they save, so you can pick up the same work on another computer. Nothing is sent to any server we run: the files go to your own storage, and everything continues to work in the browser exactly as before.

Projects found in that folder but not yet on the computer you're using appear on the Home screen under *In your sync folder, not on this computer*, one click away from opening; a project whose folder copy was saved later on another computer appears under *Newer in your sync folder*. Before writing, Map-O-Matic compares the folder copy with the one open here, even straight after a reload, so an older browser copy can't overwrite newer work: it warns and offers to load the newer version or branch off a separate copy. Renaming a project renames its file; deleting a project moves its file into a `_deleted` subfolder, so nothing in your folder is ever deleted outright. The chosen folder is remembered between visits (the browser may ask you to re-allow access). Project files in the folder end in `.mapomatic.json`; files saved by earlier versions (`.cartostudio.json`) are still read, and each is renamed the next time its project saves.

This uses the browser's File System Access API, so it needs **Chrome or Edge**; in Safari and Firefox the button explains that and the Export/Import project file route still works. Projects embed their datasets, so files can run to tens of megabytes — writes are batched rather than continuous.

## Two ways to build a map

**A. All in Map-O-Matic.** Add data in Map Maker, symbolize and filter it, then Send to Composer. Scale is calibrated automatically from the map's real coordinates (Web Mercator view only — projected views don't carry a single scale).

**B. Bring your own map image.** Made a map in other software? Export it as an image and upload it in Map Composer via *Map Frame*. Calibrate the scale bar by drawing a reference line between two points of known distance.

An optional **Live Embed** tool drops in an interactive web map (via its embed URL) for on-screen reference — it prints as a placeholder, so submissions still need an image or Map Maker frame.

## Adding data

**+ Add data ▾** in Map Maker offers three paths:

- **Upload** — GeoJSON, CSV or Excel (.xlsx/.xls) with coordinate columns, or a zipped Shapefile. Drag-and-drop onto the map also works.
- **From my library** — anything already fetched or uploaded in any project.
- **Online sources** — a built-in browser for:
  - **World base data**: Natural Earth countries, states/provinces, populated places, urban areas, land, ocean, coastline, rivers, and lakes at 110m/50m/10m detail.
  - **OpenStreetMap**: ten themed presets (schools, hospitals, parks, supermarkets, restaurants, bus stops, major roads, cycle paths, waterways, buildings) queried live via Overpass within the current map view.
  - **Open data portals**: keyword search of the Opendatasoft network or any Opendatasoft portal, any city or agency open-data hub, and public online map layers (optionally limited to the current map view). Results load straight into the map, filtered to mappable datasets, and a service with several layers asks which one. A few portals are listed as presets. Catalogues whose map services don't allow loading from a web page (the BC Data Catalogue preset, for example) show download links to upload instead.
  - **From URL**: any GeoJSON link, CSV with lat/long, or feature-service layer (…/FeatureServer/0).

Online datasets over 5,000 features prompt a choice — load all, load the first 5,000, or cancel — before committing to browser storage. Feature services are fetched page by page (up to 50,000 features), and OpenStreetMap queries include areas mapped as multipolygon relations; if a source cuts its answer short, a note says so.

**Coordinates are checked before anything is drawn.** Longitude/latitude loads straight away (and swapped columns are put right). If a table's X/Y values are in metres, the *Place points from coordinates* dialog suggests a system and previews where the data would land ("in or near Madrid", "12 km from Toronto") before converting it. The list covers every UTM zone north and south (WGS84, plus NAD83, ETRS89 and GDA2020 zones), national grids (Canada Atlas Lambert, Statistics Canada Lambert, BC Albers, USA Contiguous Albers, British National Grid, Irish Transverse Mercator, France Lambert-93, Europe LAEA, Australian Albers, New Zealand TM) and Web Mercator, and any EPSG code or proj4 string can be typed in. The suggestion is the system that puts the data nearest the layers already on the map, or the map view. GeoJSON in metres gets the same treatment. Rows with blank coordinates or at 0,0 are skipped, and a report on the map says how many rows loaded and why any were left out. A table with no coordinates at all can go straight to the Join tool.

## Map Maker: layers, projections, symbology, and spatial tools

**Side panels.** The layers panel on the left and the Style/Data/Tools panel on the right can each be dragged wider or narrower by the divider beside them. The small ‹ › tab on a divider hides the panel and brings it back, so the map can use the full screen; widths and hidden panels are remembered, and double-clicking a divider restores the default width.

**Layers panel.** Each layer card shows a visibility checkbox, name, and an **ACTIVE** badge on the selected layer, with labelled **Table**, **Zoom** and **Export** buttons and a **⋯** menu for Fields, Rename, Duplicate and Remove. A layer over 5,000 features gets one note with practical tips (filter it, use a heatmap or hexbin, keep labels and editing for smaller layers). Drag a card by its grip to reorder — the top of the list draws on top of the map. Click anywhere on a card — or its grey **Activate** button (shown on every non-active card) — to make it active. Hidden layers can't be the active one; switching one off passes the selection to the next visible layer, and whenever just one layer is switched on it becomes active automatically. Turning layers on and off updates the globe view live as well as the flat map. The toolbar's ↩/↪ buttons (or Ctrl+Z / Ctrl+Shift+Z) undo and redo Map Maker changes, including attribute edits. A **"Current layer:"** status line above the map keeps track of what you're editing, and the panel is resizable by its right edge.

**Selecting features.** Click a feature on the map to select it, or click a row in the attribute table — the two stay in sync, highlighting the feature on the map and its row in the table. Ctrl/Cmd-click adds to the selection, Shift-click selects a range of table rows, and clicking a class in the Style tab selects every feature in it. A count appears in the map toolbar with a **Selected ▾** menu: zoom to selection, invert it, clear it, copy it into a new layer, or export just those features as GeoJSON or CSV.

**Drag to select.** Make a layer active, click **⬚** on the map (or on the globe) and choose **Box** or **Lasso** in the small bar that opens (it tucks away once you pick). Drag to select the active layer's features inside the shape; hold **Shift** to add to the selection or **Alt** to remove from it. Press **Esc** or click ⬚ again to go back to panning. The selection bar then offers the usual actions (zoom to, export, new layer, clear).

**On-map controls.** The zoom group holds **+**, **−** and **✥ full extent** (zooms to the active layer, or to everything that's on when no layer is active). Below it sit the tools: **⬚ select** (drag a box or a freehand lasso), **🌐 globe view**, **📏 measure distance** (click points, double-click to finish), the **basemap-layers** panel (turn borders, labels, roads, water, buildings, land use and points of interest on and off) and **⇆ swipe**. The search box above the layer list goes to a place. The same zoom group (with ✥) appears in projected views and on the globe.

**Globe view.** The 🌐 button wraps the basemap onto a true 3-D sphere (MapLibre GL's globe) and draws your layers exactly as the flat map does: fills, outlines, graduated and proportional sizes, custom point symbols, hexbins, dot density, cartograms, heat maps and labels. Click a feature to select it and see its attributes (Ctrl/Cmd/Shift adds to the selection); ⬚ select works here too. Changes to styling appear on the globe straight away. The globe's controls are **+ / − / ✥** (whole globe) and a **compass** whose needle points north: click it for **Tilt** and **Rotation** sliders and **Reset to north, no tilt** (right-drag also tilts and turns). The tools beside them are ⬚ select, 🌐 back to the flat map, **📏 measure** (click points for a running great-circle distance, drawn along the true great-circle path; double-click to finish) and the **basemap-parts** panel. **Fit to data** frames your layers and **Back to flat map** returns to the flat map at the same place. The projection list is greyed out while the globe is open. **Share link**, **Export → Interactive web map** and **Atlas: new page** all keep the globe view.

**Basemap parts travel with the map.** Which parts of a vector basemap are switched off (labels, roads, borders…) is saved with the project and carried into share links, exported web maps and atlas pages. Share links and exported web maps also give readers a small **Basemap ▾** panel to switch parts on and off themselves.

**Basemaps.** The default set is open. Five vector styles come from **OpenFreeMap** — *Positron* (light, the default), *Bright*, *Liberty* (full streets), *Dark* and *Fiord* (muted) — built on OpenStreetMap data through the OpenMapTiles schema and rendered with MapLibre GL, so they stay crisp at any zoom. Two open raster layers sit alongside them: **OpenStreetMap** standard, and **Sentinel-2 Cloudless** — a cloud-free Copernicus mosaic from EOX, fully open but only ~10 m resolution, so it's context rather than street-level detail. For sharper imagery there are two higher-resolution options, **Satellite** and **Satellite Hybrid** (imagery plus roads, labels and boundaries from open OpenStreetMap-derived data): the reference overlay is open, but the imagery itself is proprietary (free to use with attribution, sourced from Vantor/Maxar and Earthstar Geographics), so it doesn't meet the open bar the way the rest do. The attribution for whichever basemap you pick shows under the picker; the Sentinel-2 mosaic is CC-BY-NC-SA (free for teaching and study, not commercial reuse). Projects saved before the switch that named an Esri or CARTO basemap are quietly mapped to the closest current one — old imagery projects land on Satellite.

**Projections.** Switch from the Web Mercator editing view into any of 13 projections: world (Equal Earth, Robinson, Winkel Tripel, Mollweide, Mercator, Orthographic), regional conic (Albers Equal-Area, Lambert Conformal, with adjustable centre and standard parallels), azimuthal (Equidistant, Stereographic), and historical/novelty (Gall–Peters, Goode Homolosine, Bonne). The projected view is fully interactive and behaves like the normal map: scroll or double-click to zoom (Shift+double-click zooms out), on-screen **+/−** buttons, drag to pan (or rotate the globe on Orthographic/azimuthal projections), with **Fit to data** and **Fit to world** buttons to reset the view. On interrupted projections (Goode Homolosine) everything is clipped to the lobes, so continents, Antarctica and the graticule are not smeared across the gaps. Choosing a projection while the globe is open closes the globe; the ⤢ button under the map's zoom controls zooms to all visible layers in the flat, projected and globe views; while a cartogram is on the map only the equal-area projections can be chosen. The projected view redraws to fit whenever a side panel is opened, closed or resized. An optional graticule and world-land backdrop can be toggled; raster basemaps can't be reprojected client-side, so they hide while a projection is active.

**Right panel.** Three tabs: **Style** (symbology), **Data** (Filter and Labels, in collapsible sections), and **Tools** (the spatial toolbox, grouped under headings you can fold away).

**Symbology.** Single symbol, unique values (categories — scanned across the *entire* dataset, with the top N most frequent values coloured individually and the rest grouped into an editable "Other" category, or **Show all** to list and colour every value), graduated colour (quantile / equal interval / natural breaks–Jenks / manual classification, up to 12 classes, with optional rate normalization by a second field), graduated symbol size, **proportional (unclassed) symbols** where area scales with the value, **bivariate** symbols where size follows one field and colour another, **dot density** for polygons, and **cartograms**, where the area of a unit carries its value (below). Labels support the full typography set below, with an optional halo, and can be offset into any of nine positions around a symbol (default top-right, with an adjustable distance) so they sit clear of the marker rather than on top of it.

**Density mapping.** Two further modes for point layers. **Heatmap** draws a continuous density surface (Leaflet.heat) with adjustable radius and blur, optionally weighted by a numeric field — good for showing where things cluster, though it has no classes and so generates no legend entry. **Hexbin** aggregates the points into a hexagonal lattice and shades each cell, which gives you a density map you *can* read off a legend. Cell size is set in kilometres (the lattice is built in local kilometre coordinates, so cells stay a constant real size rather than stretching towards the poles), and each cell can report a point **count** or the **sum / mean / min / max** of a chosen field. Cells can be shown as shaded hexagons or as **proportional circles** (area ∝ value) at the cell centres, and both produce a legend. **Create a layer from these bins** turns the cells into a proper polygon layer, putting the values in the attribute table where they can be filtered, classified and joined like anything else.

**Cartograms.** The one symbology that distorts the map on purpose. Area itself carries the value, so how big a unit looks reports how much of something is there rather than how much ground it covers. Four constructions sit under a single Style type. **Non-contiguous** (Olson) shrinks every unit about its own centroid until its area matches its value, leaving the densest unit at full size and opening gaps everywhere else; shapes and relative positions survive, which makes it the easiest of the four to read. **Dorling** replaces each unit with a circle sized by the value, then pushes the circles apart until none overlap, with a light pull back toward the true centroid so the arrangement still reads as the map it came from. **Demers** does the same with squares, which pack more tightly and are harder to compare by eye, so the two make a useful pair to put side by side when teaching why circles are the usual choice. **Contiguous** (Dougenik, Chrisman and Niemeyer) keeps the units joined and rubber-sheets the boundaries, pushing vertices outward from units that need to grow and inward toward units that need to shrink. The number of passes is adjustable (or tick *Keep refining* to stop automatically once areas are within 5%), and the panel reports how close the areas have come to the sizes their values ask for, so the trade-off between an accurate area and a recognisable shape is visible while the slider moves. Shared borders are snapped together and long edges densified before the transform, and each vertex's movement per pass is limited, so the units stay joined without slivers or folded borders.

Dorling and Demers layouts come from a force simulation: each symbol is pulled toward its unit's true centre, units that were neighbours on the map are pulled together until they just touch, and none may overlap, so the arrangement is compact and still reads as the map. Circles are smooth. For every construction the true boundaries can be shown faintly underneath for comparison, labels sit inside each unit, and a **Morph** slider (with a ▶ Play button) blends the real map into the cartogram, which shows exactly what the transform does. Changing the cartogram type, field or settings clears any selection, since the old shapes are gone.

Size always follows the cartogram's value field, which can be normalized by a second field to make a rate. Colour is a separate decision: keep one fill for every unit, or drive it from a second field using the full graduated or category machinery, which is how most published cartograms are built. Units with no value, a zero or a negative drop out of the three non-contiguous constructions; in the contiguous one they hold the size they have and stay part of the sheet, ready to be coloured as no-data. **Create a layer from this cartogram** turns the transformed units into a polygon layer of their own, so they can be filtered, labelled, restyled and exported like anything else.

A cartogram puts its units at invented coordinates, so selecting the mode switches the basemap off. Projections stay available but only the equal-area ones (Equal Earth, Mollweide, Albers Equal-Area, Gall–Peters, Goode Homolosine, Bonne); the others are greyed out. In a projected view the cartogram is rebuilt in that projection's own plane, so each unit's area on the projected map matches its value. Scale bars and the measure tool mean nothing on one, and the globe view falls back to the layer's true outlines. Layers are capped at 2,000 polygons, and very detailed outlines are simplified before the transform, with a note in the panel when that happens.

**Point symbols.** Click the symbol button to open a picker showing every marker at once. Thirty built-in markers grouped the way cartography texts do — *abstract* (circle, square, triangle, diamond, pentagon, hexagon, star, cross, saltire, bar), *associative* (tent, tree, water, industry, settlement, peak, rainfall, vegetation, route, place marker), and *iconic* (school, hospital, airport, port, railway, fuel, accommodation, café, waste, power). Each takes the layer's colour, size and outline, and you can upload your own SVG. The same definitions drive both the map and the projected view.

**Colours.** Every colour control opens the same picker: a saturation/lightness field with a hue slider, numeric entry in **hex, RGB, HSL, HSV, CMYK, CIE Lab, CIE LCh or OKLCh**, a palette of map colours, the colours used recently, an eyedropper for matching something already on screen, and — where it makes sense — a crossed-out **No colour** swatch for unfilled symbols, borderless polygons, or an unshaded class. The perceptual spaces are there for a reason: Lab and LCh are where you can reason about even lightness steps in a sequential scheme. A colour typed outside the sRGB gamut is flagged rather than silently changed.

**Classification histogram.** Under a graduated-colour legend, the Style tab draws the distribution of values with the class breaks as dashed lines (one dot per feature for small layers, a histogram for large ones) and the number of features in each class, so switching between quantile, equal interval and natural breaks shows exactly how the classes move. The chart is also where manual breaks are set: drag a break line to move it, click an empty part of the chart to add one, drag a line off the chart (or select it and press Delete) to remove it, and double-click a line to type an exact value. Arrow keys nudge a selected break. Any change switches the method to *Manual*, keeping the breaks where you put them; **Space evenly** resets them to equal steps. **⤢ Enlarge** opens the same chart in a wide window for fine adjustment.

**Compare two layers (swipe).** The **⇆** button under the map controls splits the map with a draggable divider: pick one layer for the left side and one for the right (⇄ swaps them). It is made for comparing two classifications of the same field, two years of the same variable, or a result against its input. It works in projected views too (the ⇆ button under the projected view's zoom buttons), and it stays on when you switch projection. Close it before sending the map to the Composer; send it to the Atlas to keep the divider.

**Colour ramps.** Classes are listed highest-first, as they read on a legend, and their ranges never share a value — one class ends where the next begins plus one step at the data's own precision (whole numbers for counts, the recorded decimals otherwise). Quantile classes hold equal numbers of features. A **Legend title** box in the Style tab replaces the default "layer — field" title on legends and shared maps. Every class colour can be edited individually, or set to no colour. Ramps import from QGIS colour-ramp XML, a plain list of hex codes, a CSS `linear-gradient(...)`, or a `.clr` colour-map file, and are interpolated to whatever class count you ask for, so 10–12 classes work even though ColorBrewer itself stops at nine. With **Manual breaks**, each break is its own editable number, with buttons to add one or space them evenly.

**Typography.** Both map labels and every Layout text element share the same type controls: 11 system fonts plus 10 Google fonts (loaded on demand), bold, italic, underline, colour, alignment, letter spacing, and line height.

**Attribute table.** Opens as a floating window you can drag and resize, so the map stays live underneath. Dock it to the bottom or the right when you want map and table side by side, with a divider to set its size. It stays open as you switch layers, reloading for whichever layer is active, and remembers its size between sessions. Long tables are paged 1,500 rows at a time, so every row can be reached and edited; clicking a feature on the map jumps to its page. Unsaved edits belong to one layer, and switching layers asks whether to save or discard them. Typed and pasted numbers keep their full value (1,234,567 stays 1234567) and leading-zero codes stay text. Its toolbar is four buttons that each expand a panel below it, marked with a caret that turns down when open (only one panel shows at a time): **▤ Field options**, **✎ Edit attributes**, **Filter** and **Σ Statistics**. **Field options** lists the layer's fields with their types and how populated they are, and holds **＋ Add field** and the **ƒx Field calculator**. **Edit attributes** has three modes — *Off* (read-only), *Type into cells*, and *Paste a column* — only one active at a time, and editing switches off automatically when you close the panel or open another one. Pasted values land on the rows in the order shown. Edits are held as *pending* changes, highlighted in the table and counted in the panel, until **✓ Save edits** writes them to the dataset; **Clear all edits** discards them. Staging edits this way is what makes them stick: earlier versions wrote each cell straight into memory without saving the dataset, so edits could disappear when the table was closed and reopened. *Apply this filter to the table* sits inside the Filter panel. **Add field** asks only for a name: the column starts empty and takes its type from what you enter, so a column of numbers behaves as numeric everywhere. Edit values in place with the edit toggle, The **ƒx Field calculator** sees only the feature's own fields (numeric ones as numbers, so values add rather than join), plus Math; write `field("Name with spaces")` for awkward field names. It asks before replacing an existing field, and its result can be undone. Open **Statistics** for a per-field summary (count, min, max, mean, median, sum, standard deviation): the statistics panel starts empty with a chooser of the layer's numeric fields, so on a wide dataset you tick only the fields you want rather than scrolling a huge table (with All / None shortcuts).

**Filtering.** Build conditions with AND/OR using =, ≠, >, <, ≥, ≤, **is one of**, is not one of, contains, does not contain, starts with, is empty and is not empty. Text matching ignores capitals, and a condition applies only once it has a value. The value box has a **populate values** button that lists every distinct value in the chosen field with its frequency and a search box, so you can pick rather than type; with *is one of*, each value you click is added to the list.

**Georeferencing** — one section of the **Tools** tab with two parts.

*Geocode addresses* takes a CSV with an address or place-name column and maps every row as a point, keeping the other columns as attributes (plus the matched name it found). It picks the likely address column for you, and you can add a place (a city, region and country) to narrow the search. It uses OpenStreetMap's free Nominatim service, so it deliberately runs one row per second and stops at 250 rows per go, with a progress bar and a Stop button; the panel says so before you start. Rows it can't match are skipped rather than mapped wrongly, and it reports how many. Results are approximate: check them on the map.

*Georeference images* places a scanned or photographed map (PNG, JPEG or WebP) on the real map so it can be traced or compared. Open the image in its viewer (drag to pan, scroll to zoom), click a point on the image, then click the same place on the map; repeat for at least three control points spread across the image. Two points give a shift, scale and rotation; three or more give an affine fit, and the table lists each point's error in metres alongside the overall average (RMS). The preview updates as points are added. Saved images appear under **Image overlays** in the Layers panel with visibility, opacity and zoom controls, and can be downloaded as a PNG with a world file (.pgw) for other GIS software. Trace over them with **Edit features**.

**Feature editing (digitising)** — the **Edit features** section of the **Tools** tab. Create a new empty **point**, **line** or **polygon** layer and draw straight into it, or select an existing layer and **Start editing** to reshape what's already there. The drawing toolbar appears at the top-right of the map (powered by [Leaflet-Geoman](https://geoman.io/)): draw points, lines, polygons and rectangles, drag whole features, move individual vertices, cut holes in polygons, rotate, and delete — with snapping to nearby vertices switched on. The map gets a gold outline while you're editing, and the panel shows **✓ Save edits** / **Cancel**, so nothing is written until you commit (Cancel warns before discarding). New features are created with the layer's existing fields present but empty, ready to fill in from the attribute table. If the layer's dataset is shared with other projects, Map-O-Matic offers to branch a private copy first, so digitising in one project can't quietly rewrite another's data. Deletions, cut holes and rotations are saved with the rest of an edit session. On layers over 3,000 features only the features in the current view become editable, and the others are carried through unchanged. Whenever you save feature edits, Map-O-Matic asks whether you want to work on the layer's attributes, and if so opens the attribute table at the new rows with the Edit attributes panel ready. Editing works on the flat Web Mercator map — not in the globe view or a projected preview.

**Joining a table** — **Tools → Join a table by a shared field** attaches the columns of a CSV, an Excel sheet or another layer's attribute table to a layer's features where a key field matches (population by neighbourhood name, census values by dissemination-area code). Key fields are suggested when names match, matching can ignore capitals, extra spaces and leading zeros, and a live preview lists the features that found no row and the rows that matched nothing. The result is a new layer; existing fields are never overwritten.

**Spatial tools** — the **Tools** tab in the right panel (all client-side, via Turf.js): table join, buffer (with dissolve), select by location (intersects / within / contains / within-distance, with invert), points-in-polygons statistics (count, sum, mean, min, max), clip, erase, intersect (with attribute join), union, dissolve by attribute, merge layers, centroids, convex hull, bounding box, simplify (Douglas–Peucker generalization), nearest-neighbour join, and a distance matrix (CSV download). Multi-part features are handled part by part, points on a shared boundary are counted once, points outside every polygon are reported, "within a distance" is measured edge to edge, and a nearest-neighbour join on one layer finds each feature's nearest *other* feature.

Each layer can be exported independently as valid GeoJSON or CSV — including any calculated fields — for use in other GIS software.

## Field Mapper: mapping with phones

The **Field Mapper** module (third tab in the top bar) builds forms for mapping in the field with phones and brings the results back as map layers. It works on its own or alongside a map project.

**Designing a form.** The left panel lists the project's forms; the centre is the designer and the right shows a live preview of the form as it looks on a phone. Give the form a title and optional instructions, then add fields: short text, number, date, choice (one), choice (several), long notes, photo or audio recording. Each field has a question or label shown on the phone, a field name that becomes the column name in the data (filled in from the label until you change it), an optional help line, a default value and a *Required* tick. Reorder fields by dragging their ⋮⋮ grip or with ↑/↓. Settings choose what can be mapped (points, lines, areas, in any mix), how features are placed (GPS, tapping the map, or both), the photo size (640–1600 px on the longest side) and the longest audio recording (30 seconds to 5 minutes). Both side panels resize and hide, so the designer and the data table can use the full width.

**Opening it on phones.** **Make link & QR code** produces a link and a QR code (downloadable as PNG). The form travels inside the link, so nothing is uploaded or installed. The phone page is headed *Map-O-Matic Field Mapper* with the form's title, and shows a map with the GPS position and its accuracy. When a form allows more than one kind of feature, a Point / Line / Area switch picks which. Two equal buttons then place it: for a point, **📍 Use my GPS location** or **👆 Tap location on map**; for a line or area, **🚶 Walk it with GPS** (a vertex is recorded every few metres as you move, with pause, resume and undo) or **👆 Tap points on map**. A bar shows the vertex count and the running length or area, and **Finish** opens the form. Photos are resized on the phone and lose their camera metadata; audio is recorded at speech quality (about 250 KB a minute) with a playback control. Everything stays in the phone's browser until deleted, and each feature can be tapped to edit.

**Getting the data back.** On the laptop, **Collected data → Receive from phone** shows a QR code and turns on the webcam. On the phone, **Send to laptop** offers three routes:

- **Scan the laptop's code** (direct link): the phone scans the laptop's code and shows a reply code for the laptop's webcam, then the two connect peer to peer and send everything, photos and audio included. No server holds the data; public STUN servers only help the two devices find each other. Some networks block direct links; the phone says so if nothing connects.
- **Show codes for the laptop to read**: the records play as a loop of QR codes, with no connection needed. This carries text only; photos and recordings are marked *on phone, not sent*.
- **Save GeoJSON**: a file with everything, to upload with **Upload a phone file** (CSV works too, without media).

Each batch received is listed with its form, record count, media count and route, and can be renamed, inspected in a table (with photo thumbnails and audio players), downloaded, or deleted. **Send to Map Maker** turns the ticked batches into layers, one per kind of feature (points, lines, areas). Records received twice (by QR codes and then by direct link or file, say) appear once and keep their photos and audio. Every record carries its time, GPS accuracy in metres, whether it was placed by GPS or by hand, and an id; lines add their length in metres and areas their area in square metres. Photos and audio play in map pop-ups, in the attribute table, and in shared and exported web maps.

The phone needs to open the link once with a signal, and then keep the tab open or reopen the same link. GPS, the camera and the microphone need an https address, so forms made from a copy on your own computer point phones to the live tool (the address is editable in the form settings).

## Atlas: a book of maps

The **Atlas** module (fourth tab) gathers a project's maps into an atlas that reads like a printed one. Click **Start an atlas**, then add pages with **+ Add page**:

- **Live map** saves the layers switched on in Map Maker, at the current view, with their styling and pop-ups. It stays interactive in the atlas (pan, zoom, click features). The quickest way to build a run of map pages is from Map Maker itself: **Send / Export ▾ → Atlas: new page** adds the current view as a page, so you can pan, zoom or restyle and send again for the next one, without leaving Map Maker. The same menu has a fold-out **Update an atlas map page** list with **View** (go back to that page's view and layers) and **Update** (replace that page's map with the current view). In the Atlas, each map page has a basemap choice (the same OpenFreeMap vector styles, Sentinel-2 and satellite options as Map Maker), a **Legend button** setting (off by default; when on, readers open and close the legend from a button on the map) and **Update from Map Maker** / **Show in Map Maker**. The standard OpenStreetMap tiles are not offered for atlas maps because their servers refuse maps shown inside an embedded frame. Any Map Maker view can become a live page: the flat map, the **globe** (it keeps its zoom, rotation and tilt), any **projected view** (Equal Earth, Robinson, Albers and the rest, redrawn live in the projection so readers can pan — or rotate, for orthographic and azimuthal views — zoom and click features; world land and graticule drawn as in Map Maker), and a **swipe comparison**, where readers drag the divider themselves and small tags name the layer on each side.
- **Map layout** captures the finished Map Composer page as an image that readers can click to enlarge; **Recapture from Map Composer** updates it. From Map Composer itself, **Send / Export ▾ → Atlas: new page** adds the layout as a page, and **Update an atlas layout page** refreshes one.
- **Image** adds a photo, scan or figure.
- **Text** adds a page of formatted writing: headings, bold and italic, lists, quotes and links.

Every page has a title, an optional caption and optional text of its own. **+ Add page** sits at the top of the page list. Drag any page in the list to move it (a teal line shows where it will land), or use ↑/↓; hover a page and click **×** twice to remove it, with **Undo** in the message that follows. The contents page and back cover are in the list too, and × removes the contents page (**+ Add page → Contents page** puts it back). Every page is edited the same way: the page (or cover preview) on top, with tidy option cards below it — for a map page, **Map** (basemap, legend button, update from or show in Map Maker) and **Page layout and text**, which holds everything about how the page is laid out, the caption and the text, next to a live preview of the printed page. Click the **Cover** to set the title, subtitle and author, the cover colour and a cover image; the preview shows the chosen design as you type. The **Back cover** takes formatted text (headings, bold, links), an image such as a logo, and a credits line set apart at the foot (course, year, licence). The right panel is kept short: how the atlas reads (**Book** shows two-page spreads with a turning-page animation, a spine and running page numbers — one page at a time on phones; arrow keys, swipes and page-edge clicks turn pages — and **Scrolling** shows one long page with section tabs), **Preview atlas**, and the design. Everything else is under **Send / Export ▾** at the top: **Share atlas link**, **Export as web page** (one HTML file to host like an interactive web map on Netlify Drop, GitHub Pages or any web host), **Download PDF** and **Preview**. Live maps need an internet connection for their basemaps.

**Sharing an atlas.** **Send / Export ▾ → Share atlas link** makes a link that opens the atlas, read-only, in Map-O-Matic. When the atlas is small enough (mostly live maps and text), the whole atlas travels inside the link and nothing needs hosting. Atlases with many images or layout pages are too large for a link: export the web page, put it online, and paste its address into the dialog, which then gives the link, a QR code and embed code for a course site. That address also becomes the atlas's web address used in the PDF.

**Design.** Seven designs set the fonts, paper, headings, page frames and cover: **Classic** (cream paper, serif type, hairline page frame, drop capitals, a framed cover), **Modern** (white pages, clean sans-serif, numbered sections, maps as rounded cards, a colour-band cover), **Field notebook** (graph paper with a red margin line, handwritten-style headings, maps taped in, a cloth cover with a paper label), **Atlas noir** (dark pages with a gold double-line frame and art-deco corners, gold-framed maps, a cover with a deco sunburst), **Map-O-Matic retro** (a DOS-style screen with a command-line prompt above each page, a status bar at the foot and a boot-screen cover) and **19th-century atlas** (aged paper, engraved-style type, double-rule borders with corner ornaments, numbered plates, a leather cover with a compass rose). A cover image is placed to suit each design: full-bleed under a title band (Classic), above a colour band (Modern), taped in as a photo (Notebook), behind a gold-framed title panel (Noir), dimmed behind the screen (Retro) or as an engraved plate in the frame (19th-century). **Custom** builds your own, with its options folded into three groups (*Page & headings*, *Fonts & colours*, *Maps & page numbers*) so the panel stays short: page frame (none, hairline, double, thick, corner marks), heading style (plain, underlined, centred, small capitals, bold or not), drop capitals, fonts for headings and body text (fourteen typefaces), colours for paper, text, headings, accent, rules and the background behind the book, map frames (none, line, double, shadow, rounded), caption style and page-number style.

**Full spreads.** Tick **Full spread** on a map, layout or image page and, in Book style, it fills both facing pages across the spine. Maps, layouts and images also take more of each page than before, inside normal book margins. The gutter shading and spine stay on top so it still reads as a bound spread; it always starts on a left page, and a blank page is added before it when needed. On phones and in Scrolling style it shows full width.

**Page layout and text.** For map, layout and image pages:
- **Fill to margins** makes the map or image take all the space inside the page margins (photos are cropped to fill; layouts are never cropped).
- **Title: Above / On the map** — lay the page title over the map or image as a **Card**, a translucent **Banner** or **Large** text with a soft halo, at the top left, top centre or bottom left. On live maps the zoom buttons move to the bottom corner so the title never covers them.
- **Caption and text** go **Below** the map, or in a **Text box** laid over it. On a full spread the choices are **Column** (right-hand page), **Text box** or **Two columns** (one per page, below).
- A text box can be placed anywhere: drag it in the preview to move it and drag its corner to resize it (it snaps to the centre of a spread). Its style is **Page** (matches the design: paper colour, soft shadow, rounded corners), **Frosted** (translucent, blurred) or **Dark**. Long text scrolls inside the box, so size it to fit before making the PDF.
- The Scrolling reading style keeps titles on the map but shows text-box text below the map, where it reads better on phones.

**Contents page.** Click it in the page list to give it its own title, an image and an introduction; the list of pages beneath is still made automatically.

**Scrolling navigation.** Each section fills one screen, with its map or layout sized to fit and centred, so nothing is cut off at the bottom. The scrolling atlas has a sticky bar of section tabs that highlights where the reader is (and scrolls sideways when there are many), a thin progress line, and ↑/↓ buttons for the previous and next section (Page Up/Page Down work too).

**PDF.** **Send / Export ▾ → Download PDF** saves the atlas as a PDF: one page per atlas page in the chosen design, a spread as one wide double page, and the cover and back cover. Live maps appear as sharp snapshots taken when the page was sent from Map Maker; if the atlas has a web address (set in the share dialog), each map carries a *View the interactive map* link. Pages are rendered at 3× screen resolution, with real links laid over them: web links in the text, the Map-O-Matic link on the back cover, and contents entries that jump to their page. The exported atlas web page has its own **⬇ PDF** button, so readers can download the same PDF. Text in the PDF is part of each page image rather than selectable.

## Map Composer: composing the page

Elements: map frame (image, or from Map Maker), inset/locator map, title and text, legend, north arrow (3 styles), scale bar, neatline (plain or tick-marked), images/logos, and sketching. Selecting an element in the **Elements** tab opens its properties.

**Cropping.** Map frames, inset maps and images can be cropped on the page: double-click the element (or use **Crop** in its properties). The full picture shows faded behind an orange box; drag or resize the box and press Enter (or click elsewhere) to apply, Esc to cancel. The crop can be changed later, and **Remove crop** restores the whole picture. The **inset/locator map** has the same live basemap engine as the main map — a basemap dropdown offering every basemap (vector, raster, satellite, or blank) and the same basemap-parts toggles (borders, place labels, roads, water, and so on) — plus optional data overlays and a locator box; it opens on whatever basemap Map Maker is currently showing so the two match by default.

All of Map-O-Matic's dialogs behave like real windows: drag one by its title bar to move it, and close it with the **✕** in the corner (the dimmed backdrop stays, so one dialog is in focus at a time).

**Right-click on the page** for a menu that saves the real pixels: *Save whole page as PNG*, or *Save selected element as PNG*, plus bring-to-front / send-to-back / delete for the selected element. Use this rather than the browser's own "Save image as…", which grabs the transparent interaction layer Fabric.js draws on top and writes a blank file.

**Checking colours.** *View as* at the bottom of the tool rail previews the page as someone with deuteranopia, protanopia or tritanopia would see it, or as a greyscale print (Machado et al. 2009 simulation). It changes only what is on screen; exports are unaffected.

**Legends** take area, point and line swatches plus bold heading rows, reorderable with ↑/↓, and can be trimmed to fit their contents so an added border sits tight around the text. The title, layer headings and item labels are styled independently — typeface, size, colour, bold and italic for each — along with row spacing and swatch size. The panel behind the legend has its own background fill and optional border.

**Scale bars** come in five styles: alternating checker, plain bar, line with end ticks, double/stacked showing two units at once, and text-only representative fraction (`1:50,000` or `1 cm = 500 m`). Set the number of divisions, bar height, colour, and label size. Drag the bar's side handles to change its length and the distance it represents follows, rounded to one decimal place (this can be turned off), switching between m/km as the number gets awkward. Scale is calibrated automatically from Map Maker, or manually by drawing a reference line between two points of known distance.

**Sketching.** Straight lines, arrows, rectangles, ellipses, polygons, a freehand pen and a highlighter. It works the way a simple graphics program does: pick a tool, draw one shape, and the pointer comes straight back with the new shape selected and its handles showing — clicking elsewhere never starts another shape by accident. Settings live in the right panel: stroke colour, width, opacity, line style (solid/dashed/dotted), end caps, and fill colour and opacity for closed shapes.

**Arrows and lines** keep their endpoints, so they can be re-aimed by dragging either round handle long after they were drawn. They also rotate: drag the round handle above the shape to swing it about its centre (hold Shift for 15° steps), or type a bearing in the panel — 0° points up the page, which is what you want for a direction arrow on a north-up map. Arrowheads are editable at any time — filled triangle, open V, barb, circle, square or none, at any size, on the end, the start, both ends or neither. Polygons can be reshaped by double-clicking them and dragging their individual points.

**Grouping, aligning and locking.** Shift-click or drag a box to select several elements, then group them (Ctrl/Cmd+G) so they move, scale and rotate as one — the quickest way to handle the shower of labels that arrives with a map from Map Maker. Double-click a group to open it and edit one part; click empty space to close it again. Ctrl/Cmd+Shift+G breaks a group apart. A multiple selection also gets align (six edges and centres) and distribute-evenly buttons; a single element aligns to the page instead. Any element can be locked against accidental edits, and unlocked again from the Layers tab.

**Zoom.** The top bar has zoom in/out buttons with the current level, plus a menu for Fit whole page, Fit width, Zoom to selection, and preset levels. Ctrl/Cmd+scroll zooms about the cursor, and Ctrl/Cmd with `+`, `−` or `0` works from the keyboard. Zoom only affects the screen — exports always render the page at full size. Templates, snap guides, neatlines and Send to Composer place things by page size, so they land in the same spot at any zoom. Map frames resize from their corners only, which keeps the map undistorted and its scale bar true.

**Borders.** Any element can carry a border: colour, width, line style (solid/dashed/dotted), corner radius, padding, and an optional drop shadow. Legends use the same controls under *Legend panel*, alongside the panel's background fill.

**Templates** are functional starting layouts — classic portrait, landscape with side panel, two-frame comparison — with placeholders you double-click to fill: a map-frame placeholder opens the image picker (or is filled automatically by Send to Composer), a legend placeholder becomes a real, editable legend, both sized to fit the slot.

Every element on the page shares the full typography controls (font, bold/italic/underline, colour, alignment, spacing, line height where applicable) and an optional **border** toggle (width, colour, padding) in its Properties panel.

The right-side Properties/Elements panel can be dragged wider or narrower by the divider beside it, or hidden with the small ‹ › tab on the divider (the width is remembered). Undo/redo (Ctrl+Z / Ctrl+Shift+Z), snap-to-centre/margin guides, and a toggleable 0.5" margin guide (never exported) are built in.

## Process log

The **📝 Process Log** button in the top bar shows the record of how the map was made: every data step as it happened (data added and where from, coordinate conversions and skipped rows, filters, spatial tools and their settings, joins and their match counts, field calculations, hand edits, digitising, exports) followed by the current design settings (basemap, projection, each layer's symbology, classification method and breaks, colour ramp, filters, labels, and the layout's elements). Copy it or download it as Markdown, then edit it into the methods section of a report. The record is saved with the project and travels with project files. **Clear** (click twice to confirm) empties the recorded steps; the design summary is always rebuilt from the current map.

## Sharing a map on the web

The quickest way to share a finished, interactive map is **Send / Export ▾ → Share link or embed…** in the top bar. It packs the whole map — your styled layers, the basemap, the view and a legend — into a single link. No upload, no account, nothing sent to any server: the map travels inside the link itself. Whoever opens it sees the live map in a clean read-only viewer (pan, zoom, click a feature for its attributes, switch basemaps). The dialog gives you the link, a **View in browser** button to preview it in a new tab, and a ready **`<iframe>` embed code** for any web page. If the globe is open, the link opens on the globe (with a button to switch to a flat map).

**One-click publish (optional).** If your instructor has enabled it, the **Send / Export ▾ → Export files… → Interactive web map** dialog also offers **Sign in with GitHub & publish**, which puts the map on your own GitHub Pages and gives you a permanent link in one step. It needs a one-time setup by the instructor (a GitHub OAuth App plus a small "gatekeeper" service) — see `map-o-matic-publishing-setup.md` and `map-o-matic-gatekeeper-worker.js`. Without it, the guided Netlify Drop route above works with no setup at all.

For this to open for other people, Map-O-Matic has to be online at a stable address — your published copy (e.g. GitHub Pages) — since the link points back to it. A link made from a file sitting on your own computer only opens on that computer. Only very large maps overflow a link; when that happens Share says so and points you to the file export below, which works at any size. (Point symbols are packed efficiently, so typical multi-layer course maps fit comfortably.)

## Course gallery

**Send / Export ▾ → 🎓 Submit to course gallery…** (in the Atlas, and in Map Maker for the current interactive map) sends the work to the class gallery page (for GEOG 270: www.jonathancinnamon.com/geog270/). The student gives a title, a short description and their name, and chooses whether the gallery shows their full name, initials or a pseudonym. They enter the class code (and their student number if the instructor uses a class list) and tick two consent boxes: agreement to public publication, and that the work is their own to share. Nothing is public until the instructor approves it.

The same dialog then shows the status (waiting, published, not accepted with the instructor's note, removed), with **Send updated version** and **Remove from gallery** (immediate). Each submission has an **edit code** for managing it from another computer (**I have an edit code**). The gallery itself, its instructor page and the small relay service behind the button are set up once by the instructor. See `GEOG270_gallery-setup-guide_2026.md`. ## Exporting


One dialog covers it all: the layout as print-ready **PDF** (compressed: a letter page at 300 dpi is about 2 MB), **PNG**, or editable **SVG** (vector — text and shapes stay editable in Illustrator, Inkscape, or similar software); the Map Maker view as a **georeferenced PNG** with a world file (Web Mercator only — projected views export as a plain image, since they don't have a single consistent ground scale); **all data layers** zipped as GeoJSON; or a full **project archive** — layout PDF + PNG, every layer, and the portable project file, all in one zip.

**Interactive web map (embed).** A separate export builds a single self-contained **HTML file** — a working Leaflet map of your styled layers, with popups, a legend, an open basemap and fit-to-data, all baked in. This is the option for very large maps or when you want a permanent URL of your own: host the file anywhere (GitHub Pages, your sync folder's public link, any web host) and it stays interactive, with a matching **`<iframe>` snippet** to paste where you uploaded it. For most maps the **Share link or embed** option above is the faster, zero-hosting route. Only the visible layers are included. After the file downloads, the dialog walks you through publishing it: a button opens **Netlify Drop** (drag the file on, it's live in under a minute), and pasting the address it gives back rewrites the embed code with your real URL.

## Notes and limitations

Map-O-Matic loads its open-source libraries from cdnjs and jsDelivr, pinned to exact versions with integrity checks. If one can't be downloaded (offline, or blocked by a network filter), the page says so rather than half-working; saved projects are unaffected. Shared links and imported project files are treated as untrusted: their contents are checked and escaped before anything is shown, so a crafted link or file can't run code in your browser.

Projects and the data library live in the browser and computer where they were created — use Export (project file or archive) as backup, especially on shared computers. Map capture (Send to Composer, inset-map snapshots) depends on the basemap server allowing cross-origin image capture; the open OpenFreeMap and Sentinel-2 basemaps are tested to work, but if a capture fails, switch basemaps or take a manual screenshot and add it via *Map Frame*. Overlay tools (clip/erase/intersect) on complex or very large datasets can be slow in the browser — simplify first if needed. The contiguous cartogram is an iterative fit rather than an exact solution: a field whose values span two or three orders of magnitude needs more passes than the default twelve, and the panel says how far off the areas still are so you can judge when to stop. OpenStreetMap and open-data-portal results reflect community/agency data quality and coverage, which varies by place and theme.
